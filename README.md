# 课链智教——基于多智能体协同的初中信息科技AI备教学评一体化系统

一套面向初中信息科技课程的双端AI备教学评一体化系统。教师端负责智能备课、资源修订、质量检测和多格式导出；学生端负责课堂资源包导入、任务学习、测评完成和AI伴学互动。系统通过标准化JSON数据包实现双端数据流转，形成"课前智能备课—课中学习记录—课后学情分析"的完整教学闭环。

## 快速开始

### 环境要求

- **Node.js** 20 或更高版本
- **操作系统**：Windows 10 / Windows 11
- **浏览器**：Chrome、Edge 等现代浏览器

### 安装与启动

```bash
# 1. 安装依赖（首次运行）
npm install

# 2. 启动开发环境（教师端 + 学生端 + 后端 并发启动）
npm run dev
```

启动成功后：

| 服务 | 地址 |
|------|------|
| 教师端（备课工作台） | http://localhost:5173 |
| 学生端（课堂学习端） | http://localhost:5174 |
| 后端服务 | http://localhost:3000 |

### 构建检查

```bash
npm run build
```

## 核心功能

### 教师端

**备课工作台（核心页面）**

- **新建课例**：输入教学需求（课题、年级、课程模块、课型、设备条件、学生基础等），支持五种课型选择，AI自动建议教学设计要点
- **AI智能生成**：一键触发6节点AI工作流，通过SSE实时查看每个节点的生成进度（学情分析→课标对齐→活动设计→测评生成→质量评估→资源组装）
- **本地生成**：AI不可用时自动切换本地规则引擎，确保系统始终可运行
- **在线编辑**：支持直接修改教学设计的每个字段（教学目标、环节、测评题等）
- **AI修订助手**：选中任意内容，通过AI进行针对性修订，教师自主确定修订结果

**资源质量检测**

- **七维度置信度评估**：课标一致性（15%）、核心素养达成度（15%）、学情贴合度（15%）、活动可操作性（15%）、资源完整度（15%）、课型匹配度（15%）、逻辑连贯性（10%）
- **核心素养证据链可视化**：展示四个核心素养（信息意识 / 计算思维 / 数字化学习与创新 / 信息社会责任）从教学目标→学习活动→任务证据→测评证据的完整链条
- **风险告警与改进建议**：自动识别资源包中的薄弱环节并给出具体改进方向

**多格式导出**

- **Word (.docx)**：标准教学设计文档，含封面、教学分析、教学环节详案、任务单、测评题、板书设计
- **HTML课堂页**：可直接在浏览器中展示的教学页面
- **JSON资源包**：结构化数据包，支持导入学生端进行课堂使用

**学情分析**

- 导入学生端导出的学习数据JSON包
- 自动生成班级学习分析报告：知识点掌握热力图、分层测评得分分布、核心素养达成雷达图
- 输出教学改进建议

**课程数据库**

- 内置192条教学指南条目（覆盖七/八/九年级三个课程模块）
- 支持关键词搜索、按年级/模块筛选
- 支持导入导出JSON格式，教师可自行扩充和维护

**精品案例**

- 内置可复用的完整课例
- 一键载入备课工作台进行编辑和适配

### 学生端

**资源包导入**

- 上传教师端导出的JSON课堂资源包，自动解析为任务单、测评题和学习支架

**任务学习**

- 查看学习目标（基于核心素养的4条固定句式目标）
- 阅读情境导入（200字真实情境描述，直接用于课堂引入）
- 按步骤完成任务：查看任务说明→填写过程记录→上传成果截图→完成反思问题
- 小组角色分工与自评互评

**在线测评**

- **基础理解**：单选题（识记层次）
- **原理阐述**：判断题（理解层次）
- **情境迁移**：简答题（应用层次）
- **创意表达**：分析题选做（创新层次）

**AI伴学**

- 苏格拉底式引导：通过追问、拆解、类比帮助学生自己找到答案
- 绝不直接给出答案——遵循"引导思考、提供支架、鼓励尝试"原则
- 根据当前课题、任务上下文提供个性化引导

**学习数据导出**

- 生成完整学习数据JSON包（含任务单填写、测评答案、AI对话记录）
- 导出供教师端学情分析使用

### AI多智能体工作流

系统核心采用基于 **LangGraph** 的6节点DAG流水线，每个节点对应一个独立角色的AI智能体：

| 节点 | 智能体角色 | 核心任务 |
|------|-----------|---------|
| `analyzeNeeds` | 初中信息科技教研员 | 提炼核心知识点与逻辑关系链、分析学生基础与设备条件、推荐教学策略 |
| `alignCurriculum` | 课标专家 | 匹配新课标条目、确定核心素养维度、生成TPACK七维分析、撰写素养导向教学目标 |
| `generateActivities` | 20年教龄一线教师 | 按指定课型六环节流程设计完整课堂活动，含教师话术、学生任务、问题链、任务单 |
| `generateAssessments` | 评价设计专家 | 生成四层分层测评题（识记→理解→应用→创新）和学情诊断表 |
| `evaluateConfidence` | 教研员 | 七维度置信度评估 + 四个核心素养完整证据链 + 风险告警与改进建议 |
| `assembleResource` | 规则引擎（非AI） | 将前5个节点输出组装为标准ClassroomResourcePackage JSON |

**容错机制**：
- AI不可用时自动回退本地规则引擎（mock.ts），确保系统始终可运行
- 工作流图级别异常时自动降级到单次AI调用（fallback.ts）
- JSON mode失败时自动降级到非JSON mode重试

**模型兼容**：所有AI调用采用OpenAI兼容协议，支持DeepSeek、通义千问、GLM等任意兼容模型

每个节点从 `SmartPrepState`（Annotation定义的不可变状态）读取上游输出，将自身结果写回状态，供下游节点使用。

### SSE实时推送

工作流生成接口（`POST /api/ai/generate-workflow`）采用Server-Sent Events协议，实时推送每个节点的执行进度：

| SSE事件 | 触发时机 | 携带数据 |
|---------|---------|---------|
| `progress` | 每个节点执行中及完成时 | stage节点名、percent百分比、detail详情 |
| `result` | 全部节点执行完成 | resource完整资源包、confidence置信度、riskAlerts风险告警 |
| `fallback` | 工作流异常触发降级 | message降级说明 |
| `error` | 生成失败 | error错误描述、detail技术细节 |
| `done` | 流结束 | message完成消息 |

### Electron桌面端

教师端和学生端均基于Electron打包为Windows便携版（.exe单文件），关键安全配置：

- `nodeIntegration: false` — 渲染进程无法直接访问Node.js API
- `contextIsolation: true` — 预加载脚本与网页内容运行在独立上下文中
- 开发模式下加载Vite Dev Server（热更新），生产模式下加载本地`dist/index.html`

## 理论依据

系统的教学设计严格建立在以下理论框架之上：

### TPACK（整合技术的学科教学知识）

Mishra & Koehler提出的TPACK框架贯穿整个课标对齐节点。`alignCurriculum`节点对每个课例生成七维分析（CK内容知识 / PK教学法知识 / TK技术知识 / PCK学科教学知识 / TCK整合技术的学科知识 / TPK整合技术的教学知识 / TPACK整合技术的学科教学知识），分析结果传入活动生成节点作为设计参考。

### 2022版义务教育信息科技课程标准

- **四大核心素养**：信息意识、计算思维、数字化学习与创新、信息社会责任——在每个课例中映射为具体的教学目标、学习活动和评价证据
- **三个课程模块**：七年级「互联网应用与创新」、八年级「物联网实践与探索」、九年级「人工智能与智慧社会」
- **五种课型**：新知建构课、项目实践课、实验探究课、技能应用课、跨学科主题课——每种课型有标准化的六环节教学流程

### 建构主义学习理论

教学设计流程体现"真实情境→问题分解→原理探究→模型建构→体系建构→迁移应用"的认知路径。任务单要求学生通过真实任务、过程记录和反思问题自主建构知识，而非被动接收。

### 分层评价（Bloom认知分类学 / SOLO分类理论）

测评题按认知层次分为四层：基础理解（识记）→ 原理阐述（理解）→ 情境迁移（应用）→ 创意表达（创新），确保评价覆盖从低阶到高阶的完整认知光谱。

### 学习支架理论（维果茨基最近发展区）

每个任务单提供`learningSupports`（学习支架），包括提示卡模板、关键词清单、连句表达框架等，帮助学生在最近发展区内完成挑战性任务。AI伴学助手采用苏格拉底式引导——拆解问题、提供类比、追问思考，而非直接给答案。

### 证据中心设计（ECD, Evidence-Centered Design）

每个核心素养对应一条完整证据链（LiteracyEvidence），包含7个环节：素养类型→教学目标→学习活动→任务证据→测评证据→评价方法→达成判定。置信度评估节点自动为四个素养各生成一条证据链，实现"以证据为中心"的评价闭环。

## 数据流转

```
┌──────────────┐                    ┌──────────────┐
│   教师端      │                    │   学生端      │
│              │  ① JSON资源包导出    │              │
│  备课工作台   │ ──────────────────► │  资源包导入   │
│  AI生成/修订  │                    │  任务单填写   │
│  质量检测     │                    │  在线测评     │
│  多格式导出   │                    │  AI伴学互动   │
│              │  ② 学习数据导入     │              │
│  学情分析     │ ◄────────────────── │  数据导出     │
│              │                    │              │
└──────────────┘                    └──────────────┘
```

1. **备课阶段**：教师在教师端输入教学需求，AI工作流生成完整课堂资源包（含教学设计、任务单、分层测评、学情诊断表）
2. **发布阶段**：教师导出JSON资源包，分发给学生
3. **课堂阶段**：学生在学生端导入资源包，完成任务单填写和在线测评，AI伴学提供实时引导
4. **反馈阶段**：学生导出学习数据JSON包，教师导入进行班级学情分析，形成教学改进闭环

## 设计原则

- **本地可运行**：无需数据库、无需云端服务、无需账号系统，单机即可完整运行
- **教师可控**：AI生成的内容必须经过教师确认、编辑后才能使用——遵循"AI建议，教师确认"原则
- **数据闭环**：标准化JSON数据包在教师端与学生端之间流转，实现"备课→学习→分析→改进"完整闭环
- **标准兼容**：AI接口采用OpenAI兼容协议，不绑定特定模型，教师可自由选择DeepSeek、通义千问等
- **容错降级**：AI不可用时自动回退本地规则引擎（mock.ts），工作流异常时自动降级到单次调用，确保系统始终可用
- **教育为本**：以2022版课标为依据、以核心素养为纲、以证据为中心、以教师专业判断为最终标准
- **安全第一**：Electron禁用nodeIntegration、启用contextIsolation；AI伴学严守"不直接给答案"的苏格拉底原则
